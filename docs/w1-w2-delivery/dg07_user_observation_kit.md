# DG-07 真实任务观察方案、记录表与邀请草稿

> [!IMPORTANT]
> **验证核心原则（对齐 W1–W2 审核结论）**
> 1. **观察对象**：尽量观察 **5 位不同参与者的首次任务**（至少 2 位，理想 5 位），自带真实系统评价筛选记录（或正在撰写的检索日志）。反复教会同一人后完成不能算作独立成功。
> 2. **先任务后操作，无实时演示**：观察开始前不演示界面操作，不代填数字，检验用户能否仅凭界面提示与校验反馈独立导出并打开有效 SVG/PNG。
> 3. **分开报告受邀测试与自然访问**：`4/5` 独立成功主要验证**可用性**；月内 `10` 个非内部、非纯样例有效导出会话只是**早期需求信号**，两者分开统计，样本不足时如实记录“样本不足”，不外推。
> 4. **隐私与数据边界**：严格保持“不上传用户输入内容”原则。

## 一、主持与观察执行脚本（供组织者使用）

### 1. 任务前准备（2 分钟）
- 请参与者准备好自己手头的一份系统评价 / Meta 分析检索与筛选数字记录（包含：数据库检出数、去重数、初筛排除数、全文未获取数、全文排除理由及数量、最终纳入研究数 studies 与报告数 reports）。
- 发送测试链接：`https://diagrflow.com/editor`（注意：**不要**带 `?internal=1`，除非是内部人员自测；如果是受邀用户测试，请在观察表记录其任务开始时间以便与后台会话核对，或使用受邀观察记录表直接定性定量记录）。

### 2. 任务指令（直接念出或发给参与者，不做额外解释）
> “请你使用这个网页工具，把你手头这组系统评价的筛选数据录入进去，生成一张符合 PRISMA 2020 规范的流程图，然后下载 SVG 或 PNG 文件，并在你的电脑上打开下载好的图片确认数字和排版是否正确。
> 在操作过程中，请尽量自己完成；如果遇到卡住超过 2 分钟无法继续的地方，可以告诉我。”

### 3. 成功 / 帮助 / 失败判定口径

| 结果分类 | 判定标准 |
|---|---|
| **独立成功（Independent Success）** | 参与者为**首次使用**，全程**0 次实质性操作指导**，完成本人筛选记录录入、通过校验（无算术或语义未确认拦截）、成功下载 SVG 或 PNG，并在本地打开确认数字与框图完整可读。 |
| **受助完成（Assisted Completion）** | 参与者在操作中因概念困惑（如不理解 `Studies` 与 `Reports` 区别、不理解细分项必须等于总数）或界面阻碍请求帮助，经主持者提示（记录帮助次数 $\ge 1$）后完成导出。**不计入“独立成功”分子**。 |
| **任务失败（Task Failure）** | 参与者放弃任务、导出的文件打不开/存在裁切或数字错误而未被拦截、或因严重缺陷无法完成。 |

## 三、自愿参与者邀请草稿（供你自行发送，AI 不外联）

### 草稿 A：发给正在写系统评价 / Meta 分析的同事或研究生（中文）
> **主题 / 消息**：想请教你帮测一个 PRISMA 2020 流程图小工具（约 5–8 分钟）
>
> 嗨 [姓名]，
> 我最近在做能够根据检索筛选数字直接生成 PRISMA 2020 流程图的网页工具（Diagrflow，免费免登录，直接导出无水印 SVG/PNG）。
> 如果你手头正好有正在写或已完成的系统评价筛选记录（各数据库检出数、去重、初筛、全文排除理由、纳入 studies/reports 数），想邀请你花 5–8 分钟做一次真实的首次录入测试。
> 过程非常简单：我把链接发给你，你不用看任何教程直接试着把自己的数据填进去并导出一张图，我只看有哪些提示不够清楚的地方。你的任何具体数据都只在本地浏览器生成图片，不会上传。
> 不知道你这周方便抽几分钟试试吗？
